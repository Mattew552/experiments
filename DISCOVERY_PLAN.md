# Автоматическое обнаружение вентиляторов — план для Test

Подробные варианты backend, ограничения текущего мастера и порядок расширения описаны в [HARDWARE_SUPPORT.md](HARDWARE_SUPPORT.md).

## Что уже возможно без аппаратных команд

LibreHardwareMonitor перечисляет датчики температуры, RPM и доступные элементы Control. В `Test` добавлена read-only выборка активных тахометров на главном экране и в окне диагностики. Она не приписывает тахометрам физические роли и не разрешает запись. Температура CPU выбирается из подходящего датчика процессора AMD или Intel; 0 °C и похожие по имени датчики платы отклоняются. Нулевой RPM может означать пустой разъём, остановленный вентилятор или отсутствие тахосигнала; по одному чтению это не различить.

## Почему полного автоуправления пока нет

На проверенной плате библиотека называет входы `Fan #N`, а не `CPU_FAN1` или `SYS_FAN3`. Даже совпадение номера `fan/N` и `control/N` не доказывает соответствие конкретному разъёму или проводке. Разветвитель даёт один управляющий канал и обычно один тахосигнал для двух физических вентиляторов. Программе неизвестно, какие разъёмы заняты и какой вентилятор охлаждает CPU. Автоматически писать в неизвестный канал поэтому нельзя.

## Что делает кнопка «Подключить новую систему»

После проверки температуры CPU и отсутствия обнаруженных конкурирующих программ кнопка последовательно выбирает доступные каналы Super I/O с текущим значением ниже 95%. Каждый канал получает 100% на три секунды; отдельный сторож сам возвращает исходный режим не позднее шести секунд. Приложение сравнивает RPM до и после и показывает вероятные пары `Control` → `Fan`. Если RPM не выросли или выросли у нескольких датчиков, результат остаётся неопределённым. Никаких команд GPU и автоматического 0% нет. На других ПК этот сценарий ещё не проверен аппаратно.

## Следующий безопасный этап

1. Пассивно определить модель платы, Super I/O, достоверную температуру CPU и список активных RPM. Графики найденных тахометров без физических ролей уже реализованы; проверить их на других ПК.
2. Проверить мастер на разных платах: текущая версия использует одну короткую пробу на 100%; при исходных 95–100%, нестабильном RPM или отсутствии тахосигнала она не определяет канал.
3. Добавить подтверждение физической группы пользователем по кабелю или наблюдению за крыльчаткой. Лишь затем разрешать запись в обычном режиме. Поддержать произвольное число групп вместо фиксированных ролей текущего ПК.
4. Хранить результат только для этой установки Windows. При переносе настроек, смене платы или недоступном идентификаторе машины управление блокировать.
5. Отдельно проверять 0% только для подтверждённых корпусных каналов при работающем CPU-кулере. Задний Molex и подсветка не участвуют.

Модель платы может помочь предложить названия разъёмов, но не подтверждает фактическую проводку. Универсальное управление с нулём действий пользователя не будет безопасным для неизвестной сборки.
