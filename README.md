# FanGuardian

Приложение для Windows с автоматическим чтением доступных датчиков вентиляторов. Управление аппаратно проверено только на MSI B450 TOMAHAWK MAX с контроллером Nuvoton NCT6797D. На других ПК программа показывает найденные тахометры и температуру CPU, когда библиотека может их прочитать, но не отправляет команды без привязок, подтверждённых именно на этом компьютере.

## Запуск

Распакуйте архив целиком и запустите `FanGuardian.exe`. Для этой сборки нужен установленный .NET 9 Desktop Runtime. Для чтения датчиков платы требуется работающий PawnIO и разрешение запроса UAC. Приложение не устанавливает драйвер.

Главный экран показывает три режима, температуру CPU, графики обнаруженных тахометров, выбор ручного профиля и ссылку «Настроить кривые». На данном проверенном ПК графики подписаны физическими группами; на других ПК они подписаны только именами датчиков. RPM CPU отдельно выводится после подтверждения соответствующего датчика. Сохранённые кривые задаются точками `температура:процент`, например `30:40, 50:55, 70:80, 85:100`. Профили «Тихий», «Сбалансированный» и «Производительный» имеют разные исходные кривые.

В ветке `Test` кнопка «Подключить новую систему» собирает несколько устойчивых показаний, повышает один канал до 100%, проверяет возврат RPM и повторяет опыт. Сопоставляются датчики только того же контроллера. После успешной проверки можно выбрать назначение CPU/корпус, дать группе название и сохранить её для ручного режима. Минимум новой группы не ниже наблюдавшегося исходного duty и 40%; остановка ей не разрешается. Если вентилятор сейчас не вращается, ручной режим не включается до подтверждения работающего тахометра.

Назначение автоматически подставляется по явным именам `CPU_FAN`, `SYS_FAN`/`CHA_FAN` либо профилю точной модели платы. Для MSI B450 TOMAHAWK MAX профиль даёт `CPU_FAN1`, `SYS_FAN3`, `SYS_FAN4` по ранее проверенному сопоставлению. Безымянные `Fan #N` на других платах не получают выдуманную роль; `CPU_OPT`, помпы и GPU не считаются обычным CPU-кулером. Название разъёма описывает ожидаемое подключение, поэтому перед сохранением нужно проверить фактическую проводку. Уже настроенным группам можно исправить назначение, сохранив кривые; CPU никогда не наследует разрешение остановки.

Если после настройки кнопка «Корпусные выключены» ещё не имеет проверенных остановочных групп, она открывает однократную проверку остановки/повторного запуска. Её также можно открыть через «Сервис → Проверить остановку корпусных». После подтверждения, что выбраны именно корпусные вентиляторы, worker по очереди задаёт 0% максимум на пять секунд, затем самостоятельно задаёт 100% для запуска, проверяет RPM и возвращает исходный режим. Требуются работающие CPU-тахометры и CPU ниже 60 °C. Только подтверждённые остановка, запуск и возврат дают `StopVerified`; неподдерживаемая остановка не лишает группу ручного ненулевого режима. CPU/PUMP/GPU не допускаются к такой проверке. Эта новая процедура аппаратно ещё не проверялась.

Проба ограничена независимым монотонным таймером worker (20 секунд на один подъём); закрытие окна/потеря heartbeat также вызывает попытку возврата. Это программный сторож, а не гарантия при отказе драйвера или самого worker. При неподтверждённом возврате, ошибке IPC или сохранения привязок управление блокируется в текущей сессии. Отсутствие роста RPM **не** означает пустой разъём. Исходные 95–100%, сильный шум, несколько реакций и общий тахометр нескольких выходов остаются неопределёнными.

- **Исходный режим платы:** приложение возвращает сохранённое состояние; это не определение фактического BIOS/ручного режима firmware.
- **Корпусные выключены:** останавливаются только корпусные группы с отдельно проверенной остановкой; CPU и остальные группы остаются под управлением платы. На первоначально проверенном ПК это только две передние группы; задний Molex продолжает работать.
- **Ручной режим:** произвольное число настроенных CPU/корпусных групп следует выбранным кривым в подтверждённом ненулевом диапазоне. Помпы и неизвестные роли автоматически не управляются.

Температура выбирается из датчиков самого процессора AMD или Intel: Tctl/Tdie, Tctl или CPU Package. Значение 0 °C и датчики материнской платы с похожим названием не используются как температура CPU. При недостоверной температуре, опасном нагреве или потере RPM CPU управление сбрасывается. Приложение никогда не отправляет команды вентиляторам GPU. Отдельный процесс хранит исходное состояние регистров вентилятора и восстанавливает его при завершении или потере связи с окном. Проверены обычные переходы режимов и принудительное завершение окна на указанном ПК; отказ самого сторожа и сон/пробуждение остаются непроверенными.

Настройки и журналы хранятся в `%LOCALAPPDATA%\FanGuardian` вне репозитория. Schema 4 добавляет локальный hash данных платы/BIOS; исходные серийные номера не сохраняются. Перед миграцией создаётся `settings.json.before-schema4.bak`. Старые проверенные привязки первоначального MSI сохраняются при совпадении установки Windows и модели платы; другие старые привязки отключаются. Изменение аппаратного отпечатка отключает управление. Если serial недоступен, резервный отпечаток модели/BIOS не гарантирует обнаружение замены на идентичную плату; изменение проводки всегда требует повторной проверки.

Чтение и запись принадлежат одному процессу worker и одному экземпляру LHM. Запись разрешена только явным возможностям и каталогом проверенной по исходникам процедуры восстановления: старые семейства NCT и несколько Fintek. ITE, Winbond, NCT668* и неизвестные драйверы пока остаются без записи. USB, ноутбуки и другие ОС ещё не реализованы. Новая версия `Test` проверена программными тестами, но аппаратно после этих изменений не проверялась даже на первоначальном ПК; остальные устройства каталога не объявляются проверенными.

## Диагностика и сборка

План поддержки других плат, USB-контроллеров, ноутбуков и ОС: [HARDWARE_SUPPORT.md](HARDWARE_SUPPORT.md). Исследованные способы доступа не означают аппаратную проверку перечисленных устройств.

`FanGuardian.exe --probe` выводит датчики без аппаратной записи. `FanGuardian.exe --self-test` запускает проверки логики на подставных данных. Для сборки из исходников требуется .NET 9 SDK:

```powershell
dotnet restore FanGuardian/FanGuardian.csproj
dotnet build FanGuardian/FanGuardian.csproj -c Release
```

`FanGuardian.exe --ui-smoke preview.png` открывает окно на подставных датчиках и сохраняет снимок; LHM, worker и настройки пользователя в этом режиме не используются. Самопроверки включают миграцию, произвольные группы, отказ записи/возврата, повторную пробу, шум и запрет GPU. Они не заменяют аппаратные испытания. Переход на .NET 10 LTS и самодостаточная упаковка остаются следующим этапом распространения; на текущей машине установлен только SDK 9.

Библиотека [LibreHardwareMonitorLib 0.9.6](https://www.nuget.org/packages/LibreHardwareMonitorLib/0.9.6) распространяется по MPL-2.0. [PawnIO](https://github.com/namazso/PawnIO) устанавливается отдельно и имеет собственную лицензию. Разъёмы подсветки 5V ARGB не входят в приложение; напрямую соединять их с 12V JRGB платы нельзя.
